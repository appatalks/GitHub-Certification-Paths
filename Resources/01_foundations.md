# GitHub Foundations (GH-900)

GitHub Foundations is the on-ramp certification: the goal is to understand
GitHub as a platform for version control, collaboration, planning, security,
and modern software delivery. You do not need to be a specialist programmer;
you do need to be comfortable explaining what GitHub features are for and when
to use them.

## What to Know

The official GH-900 study guide lists these weighted domains:

1. **Understand Git and GitHub basics (25-30%):** version control, GitHub accounts, GitHub Flow, Markdown, and core terminology.
2. **Work with GitHub repositories (10-15%):** repository structure, files, templates, branches, visibility, maintenance, and insights.
3. **Collaborate using GitHub (10-15%):** issues, pull requests, reviews, discussions, notifications, Gists, Wikis, and Pages.
4. **Apply modern development practices (10-15%):** Actions, Copilot, Codespaces, `github.dev`, and software lifecycle workflows.
5. **Manage projects with GitHub (5-10%):** Projects, layouts, labels, milestones, workflows, and insights.
6. **Understand privacy, security, and administration (10-15%):** authentication, permissions, roles, visibility, branch protection, teams, and organization settings.
7. **Explore the GitHub community (5-10%):** open source, GitHub Sponsors, Marketplace, InnerSource, follows, forks, and templates.

Use the [Learning about GitHub](https://docs.github.com/en/get-started/learning-about-github)
hub as your glossary. Pair it with the [pull request documentation](https://docs.github.com/en/pull-requests/collaborating-with-pull-requests)
and [Projects documentation](https://docs.github.com/en/issues/planning-and-tracking-with-projects)
to turn vocabulary into workflows.

## Hands-On Missions

### Mission 1: Ship a Tiny Change

Use [Introduction to GitHub](https://github.com/skills/introduction-to-github)
to create a branch, commit a Markdown change, open a pull request, review it,
and merge it. Be able to narrate what changed at each step.

### Mission 2: Plan the Work

Create a small Project with an issue, labels, a custom field, and two views.
Connect the issue to a pull request, then explain how the project differs from
the repository's code and discussion history.

### Mission 3: Map the Platform

Draw a one-page map connecting a repository to issues, pull requests, Actions,
Packages, Codespaces, and Copilot. For each product, write one use case and one
permission or security consideration.

## Quick Self-Check

- Can you distinguish a branch, a fork, a clone, and a pull request?
- What is the difference between an issue, a discussion, and a Project item?
- Which settings control repository visibility and who can contribute?
- Why should a pull request be reviewed before it is merged?
- Which GitHub products help plan, build, automate, secure, and deliver software?
