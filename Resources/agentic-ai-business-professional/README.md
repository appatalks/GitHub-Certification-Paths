# GitHub Certified: Agentic AI Business Professional (GH-700)

Official exam title: **GH-700: Enhancing Operational Efficiency with Agentic AI**.

GH-700 is for business professionals who use GitHub and GitHub Copilot to improve
work quality, speed, and scale. The role can include product and program
managers, technical project managers, and business analysts. Deep software
development or coding experience is not required. Focus on choosing useful
workflows, setting appropriate controls, and evaluating outcomes with human
judgment.

## What to Know

Microsoft's study guide lists these four weighted skill areas. The percentages
and objectives can change, so check the official guide before exam day.

1. **Use GitHub platform features (20-25%):** apply management policies and governance; evaluate budgets, token usage, privacy, risk, and responsible AI; choose models, skills, prompts, instructions, and MCP servers appropriately; plan work with projects, issues, views, and collaboration; track work with pull requests and wikis.
2. **Enhance productivity by using GitHub Copilot (20-25%):** choose models and agents for a business task; manage chat sessions and attach relevant context; write prompts and instructions that specify inputs, desired outputs, and constraints; use checkpoints; create and manage custom agents with guardrails and review their activity.
3. **Design and implement agentic workflows and automations (25-30%):** identify valuable use cases, decompose processes into tasks, define decision criteria, and select workflow patterns; configure workflow files, schedules, permissions, folder structures, instructions, and self-critique; configure automation triggers, prompts, models, and tools; install or create skills and connect workflows to MCP servers.
4. **Perform human-in-the-loop tasks for agentic workflows (20-25%):** identify decisions requiring human judgment; select interactive, plan, or autopilot operation and escalation paths; approve, reject, or revise requests; intervene during execution, resolve failures, or stop a run; validate outputs and monitor workflow runs against requirements.

## Hands-On Missions

### Mission 1: Find the Business Case

Choose a repeatable business process. Map its steps, inputs, decisions, expected
outputs, and risks. Identify which tasks are suitable for automation, where an
agent may help, and what success measure would show a real improvement.

### Mission 2: Design a Governed Workflow

Sketch an agentic workflow for one part of that process. Specify the trigger,
instructions, context, tools, model choice, permissions, output location, and
failure behavior. Add budget or token limits and explain how the workflow follows
organizational policies.

### Mission 3: Put Human Review in the Loop

Mark decisions that require approval, define escalation conditions, and decide
when the workflow should pause or stop. Review a sample output against the
business requirements, record a correction, and describe how you would monitor
the workflow over time.

## Quick Self-Check

- How would you compare the expected business value of an agentic workflow with its cost and risk?
- When should a task use a GitHub project, issue, pull request, or wiki to coordinate work?
- What makes an instruction or prompt reliable for a defined business output?
- How do permissions, tools, skills, MCP servers, and models affect a workflow's behavior and governance?
- Which decisions require human approval, and what should happen when an agent fails or produces an unsuitable result?
